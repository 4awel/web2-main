1. XSS (Cross-Site Scripting) Риск: ВЫСОКИЙ

Межсайтовый скриптинг - внедрение вредоносного JavaScript-кода

🔴 Описание уязвимости

Злоумышленник может внедрить вредоносный JavaScript-код через поля ввода (имя, email) или через данные из JSON файла. При выводе без экранирования скрипт выполнится в браузере других пользователей.

Пример атаки: Ввод в поле имени: <script>alert('XSS')</script>

⚠️ Уязвимый код

<?php
// Прямой вывод без экранирования
echo $user['name'];
echo $user['email'];
?>

✅ Защищённый код

<?php
// Функция для безопасного вывода
function h($string) {
    return htmlspecialchars($string, ENT_QUOTES | ENT_HTML5, 'UTF-8');
}

// Использование
echo h($user['name']);
echo h($user['email']);
?>

🛡️ Применённые методы защиты:

  • Экранирование специальных символов HTML с помощью htmlspecialchars()
  • Валидация входящих данных strip_tags() и filter_var()
  • Установка CSP заголовка: Content-Security-Policy: default-src 'self'
  • Установка X-XSS-Protection: 1; mode=block

2. Information Disclosure Риск: СРЕДНИЙ

Раскрытие конфиденциальной информации

🔴 Описание уязвимости

Злоумышленник может получить доступ к путям файлов, версии PHP, содержимому конфигурационных файлов и отладочной информации.

⚠️ Уязвимый код

<?php
error_reporting(E_ALL);
ini_set('display_errors', 1);
// Прямой доступ к config.php
?>

✅ Защищённый код

<?php
// Отключение показа ошибок
ini_set('display_errors', 0);
ini_set('log_errors', 1);
error_reporting(E_ALL);

// Защита конфигурационных файлов
defined('APP_START') or die('Direct access not allowed');

// Скрытие информации о сервере
header('X-Powered-By: unknown');
?>

🛡️ Применённые методы защиты:

  • Отключение показа ошибок в production
  • Защита конфигурационных файлов через defined('APP_START')
  • .htaccess с ServerSignature Off и Options -Indexes
  • Пользовательская обработка ошибок без раскрытия деталей

3. SQL Injection Риск: КРИТИЧЕСКИЙ

Внедрение вредоносного SQL-кода в запросы к базе данных

🔴 Описание уязвимости

При использовании SQL БД злоумышленник может внедрить вредоносный SQL-код, получая несанкционированный доступ к данным.

⚠️ Уязвимый код

<?php
$id = $_GET['id'];
$query = "SELECT * FROM users WHERE id = " . $id; // УЯЗВИМО!
?>

✅ Защищённый код

<?php
// Подготовленные запросы PDO
class Database {
    private $pdo;
    
    public function getUserById($id) {
        $stmt = $this->pdo->prepare('SELECT * FROM users WHERE id = :id');
        $stmt->execute([':id' => $id]);
        return $stmt->fetch();
    }
}
?>

🛡️ Применённые методы защиты:

  • Использование подготовленных запросов (PDO)
  • Валидация типов данных через filter_var()
  • Отключение эмуляции подготовленных запросов
  • Для JSON: рекурсивная очистка данных

4. CSRF Риск: ВЫСОКИЙ

Cross-Site Request Forgery - подделка межсайтовых запросов

🔴 Описание уязвимости

Злоумышленник может заставить авторизованного пользователя выполнить нежелательные действия (удаление данных, изменение информации).

✅ Защищённый код

<?php
session_start();

function generateCSRFToken() {
    if (empty($_SESSION['csrf_token'])) {
        $_SESSION['csrf_token'] = bin2hex(random_bytes(32));
    }
    return $_SESSION['csrf_token'];
}

function verifyCSRFToken($token) {
    return hash_equals($_SESSION['csrf_token'], $token);
}

// В форме
<input type="hidden" name="csrf_token" value="<?php echo generateCSRFToken(); ?>">
?>

🛡️ Применённые методы защиты:

  • Генерация и проверка CSRF-токенов
  • Использование hash_equals() для защиты от timing attacks
  • Установка SameSite=Strict для cookies
  • Проверка HTTP Referer (дополнительно)

5. File Inclusion Риск: ВЫСОКИЙ

Включение внешних файлов

🔴 Описание уязвимости

Злоумышленник может включить (include) внешние файлы, что приводит к выполнению вредоносного кода или раскрытию данных.

✅ Защищённый код

<?php
function safeInclude($file) {
    $allowedFiles = ['config.php', 'functions.php'];
    
    if (in_array($file, $allowedFiles)) {
        include_once(__DIR__ . '/' . $file);
    } else {
        die('Access denied');
    }
}

// Использование
safeInclude('config.php');
?>

🛡️ Применённые методы защиты:

  • Использование белых списков разрешённых файлов
  • Валидация путей через realpath()
  • Проверка, что файл находится внутри проекта
  • Запрет включения файлов из пользовательского ввода

6. File Upload Риск: ВЫСОКИЙ

Загрузка вредоносных файлов на сервер

🔴 Описание уязвимости

Злоумышленник может загрузить вредоносный файл (shell.php) на сервер, что приводит к выполнению кода или DoS-атаке.

✅ Защищённый код

<?php
class SecureFileUpload {
    private $allowedTypes = ['image/jpeg', 'image/png'];
    private $maxFileSize = 5242880; // 5 MB
    
    public function upload($file) {
        // Проверка MIME типа
        $finfo = finfo_open(FILEINFO_MIME_TYPE);
        $mimeType = finfo_file($finfo, $file['tmp_name']);
        
        if (!in_array($mimeType, $this->allowedTypes)) {
            throw new Exception('File type not allowed');
        }
        
        // Генерация безопасного имени
        $safeName = bin2hex(random_bytes(16));
        
        // Перемещение файла
        move_uploaded_file($file['tmp_name'], '/uploads/' . $safeName);
    }
}
?>

🛡️ Применённые методы защиты:

  • Проверка реального MIME типа (не доверять расширению)
  • Ограничение размера файла (5 MB)
  • Генерация безопасного имени файла
  • .htaccess с php_flag engine off в папке загрузок
  • Сканирование на вирусы (ClamAV)
